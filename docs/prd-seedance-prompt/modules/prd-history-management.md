## 1. 模块概述

### 1.1 模块职责

历史管理模块负责记录和管理用户所有提示词优化结果，使用户的创作资产得以沉淀。核心价值是「让优质提示词可复现、可迭代」——用户可以随时回顾历史优化记录、在历史版本基础上继续迭代、对比不同版本的提示词差异。

### 1.2 模块范围

| 包含 | 不包含 |
|------|--------|
| 历史优化记录的自动保存 | 生成的视频文件存储（由 `api-preview` 模块处理） |
| 历史记录的列表浏览与搜索 | 团队间历史共享（Pro 后期功能，v1.1 迭代） |
| 版本对比展示 | 历史记录的公开分享功能 |
| 历史记录导出（JSON/TXT） | — |
| 删除与批量清理 | — |

### 1.3 相关模块

| 模块 | 标识 | 关系 | 说明 |
|------|------|------|------|
| 提示词优化引擎 | `prompt-optimizer` | 上游依赖 | 优化完成后自动触发历史记录保存 |
| 模板库 | `template-library` | 双向协作 | 历史记录可另存为模板；模板使用记录写入历史 |
| API 集成预览 | `api-preview` | 上游依赖 | 视频预览任务 ID 关联到对应历史记录 |

## 2. 功能需求

### 2.1 功能概览

| 功能点 | 描述 | 优先级 | R | I | C | E | RICE 分 | 状态 |
|--------|------|--------|---|---|---|---|---------|------|
| 历史记录列表与版本对比 | 展示历史优化记录，支持版本对比和基于历史再优化 | P1 | 7 | 1 | 80% | 0.5 | **11.2** | 待开发 |
| 历史记录导出 | 将单条或批量历史记录导出为 JSON/TXT | P2 | 4 | 0.5 | 50% | 0.5 | **2.0** | 待开发 |

### 2.2 功能详细描述

#### 2.2.1 历史记录列表与版本对比

- **描述**：展示用户所有提示词优化记录，按时间倒序排列，支持按关键词检索，并提供版本对比功能（选任意两条记录，左右分栏对比差异）
- **输入**：
  - 自动触发：每次提示词优化完成后，由优化引擎模块调用 `POST /api/history` 自动保存
  - 用户操作：浏览历史列表、搜索关键词、点击「对比」选择两条记录、点击「在此基础上优化」（将该记录内容导入编辑器）
- **处理逻辑**：
  1. 历史列表每页15条，时间倒序，支持按日期范围筛选
  2. 列表卡片展示：创建时间、输入描述摘要（前60字）、输出提示词摘要（前60字）、关联视频预览状态（若有）
  3. 版本对比：选择左侧记录后，右侧选择另一条，逐句 Diff 高亮（新增绿色/删除红色/相同灰色）
  4. 「在此基础上优化」：将该历史记录的输入描述和参数配置，预填到优化编辑器并跳转
  5. Free 用户历史记录限 50 条（超出后最旧记录自动删除，删除前7天内提醒）；Pro 用户无限制
- **输出**：历史记录列表页 + 版本对比 Drawer/弹窗
- **异常场景**：
  - 历史记录为空（新用户）：展示引导页「还没有历史记录，去优化你的第一个提示词」+ CTA 按钮
  - 自动保存失败（网络中断）：本地 IndexedDB 暂存，下次联通时同步

#### 2.2.2 历史记录导出

- **描述**：将单条或多条历史记录导出为结构化文件，支持 JSON 格式（含元数据）和 TXT 格式（仅提示词文本）
- **输入**：
  - 单条导出：历史记录详情页点击「导出」
  - 批量导出：列表页勾选多条 → 点击「批量导出」（最多 50 条）
  - 格式选择：JSON（含输入描述、参数配置、时间戳、质量评分）或 TXT（仅提示词文本）
- **处理逻辑**：
  1. JSON 格式：序列化完整历史记录结构，生成 `seedance-history-{时间戳}.json`
  2. TXT 格式：每条记录为一段，含分隔符，生成 `seedance-prompts-{时间戳}.txt`
  3. 浏览器触发文件下载
- **输出**：浏览器下载 JSON 或 TXT 文件
- **异常场景**：选择超过 50 条时，提示「批量导出最多50条，请缩小选择范围」

#### 2.2.3 删除与批量清理

- **描述**：支持删除单条历史记录和批量清理（按日期范围或全部清空），操作前需用户二次确认
- **输入**：
  - 单条删除：历史记录右上角「删除」按钮
  - 批量清理：「清理历史」入口，可选「30天前」、「全部」
- **处理逻辑**：
  1. 删除前弹出确认对话框（单条：「确认删除此记录？」；批量：「确认清除 N 条历史记录？此操作不可撤销」）
  2. 硬删除（数据库真删除，不做软删除以节省存储）
  3. 操作成功后列表刷新，展示暑假 Toast
- **输出**：删除成功 Toast + 列表更新
- **异常场景**：删除操作失败（服务端错误）：提示「删除失败，请重试」，不清空前端状态

## 5. 交互设计与原型

### 5.1 关键交互流程

```
进入历史管理页（Tab：全部 | 我的收藏）
  → 浏览历史卡片列表（时间倒序）
    → 点击单条记录展开详情 Drawer
      → 「在此基础上优化」→ 跳转编辑器（预填）
      → 「对比版本」→ 选择第二条 → 左右 Diff 展示
      → 「另存为模板」→ 跳转模板创建表单
      → 「导出」→ 格式选择 → 文件下载
      → 「删除」→ 确认对话框 → 删除
```

## 6. 依赖、风险与技术参考

### 6.1 外部依赖

| 依赖项 | 提供方 | 状态 | 影响范围 |
|--------|--------|------|----------|
| IndexedDB（离线暂存） | 浏览器 API | ✅ 已确认（Web 标准） | 网络中断时的本地缓存 |

### 6.2 风险项

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| 用户数据增长导致存储成本激增 | 中 | 中 | Free 用户 50 条上限阻断无节制增长；设置定期清理 90 天以上无活跃用户数据的策略（提前告知用户） |

### 6.3 技术参考

- **模块级架构文档**：[architecture-seedance-prompt-history-management.md](architecture-seedance-prompt-history-management.md) v1.0.0
- **核心数据对象**：`prompts`（user_id, input_text, output_json, quality_score, params_snapshot, version_count）、`prompt_versions`（prompt_id, version_num, output_json, params_snapshot, change_summary）
- **核心 API 端点**：`GET /api/v1/history`（游标分页）、`POST /api/v1/history`、`DELETE /api/v1/history/:id`、`GET /api/v1/history/:id/versions`、`GET /api/v1/history/export`
- **Diff 算法**：`diff-match-patch` 库，词级别文本差异；前端 `Web Worker` 异步计算（超長文本避免卡顿）
- **离线缓存方案**：IndexedDB（`idb` 库）+ Service Worker Network First 策略；缓存最近 50 条，按 created_at 淡汰
- **分页方式**：游标分页（以 `created_at` 时间戳为 cursor），避免实时写入场景下 offset 分页的重复/跳过问题
