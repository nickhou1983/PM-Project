## 1. 模块概述

### 1.1 模块职责

提示词优化引擎是 Seedance Prompt Studio 的核心模块，承担将用户自然语言创意描述转化为 Seedance 模型可高效理解的结构化提示词的职责。模块通过 LLM 驱动的提示词理解与重写算法，结合 Seedance 2.0 多模态生成特性（T2V镜头控制、光影风格、主体运动、音视频协同），按标准化的「主体+场景+镜头+光影+运动+风格」六维结构输出高质量提示词。

该模块是产品差异化的核心竞争力所在，直接决定用户的核心体验。

### 1.2 模块范围

| 包含 | 不包含 |
|------|--------|
| 自然语言输入的接收与处理 | 视频内容合规审核（由独立审核服务处理） |
| LLM 调用与流式输出管理 | 视频生成任务提交（由 `api-preview` 模块处理） |
| 六维结构化提示词生成 | 模板的存储与管理（由 `template-library` 模块处理） |
| 多维度参数可视化调校 | 历史记录的持久化（由 `history-management` 模块处理） |
| 提示词质量评分与建议 | 用户账号/订阅管理（由 `user-system` 模块处理） |
| 一键复制导出 | — |

### 1.3 相关模块

| 模块 | 标识 | 关系 | 说明 |
|------|------|------|------|
| 历史管理 | `history-management` | 下游消费 | 优化完成后，优化结果可保存到历史模块 |
| 模板库 | `template-library` | 上游依赖 | 用户从模板库选择模板后，作为输入导入优化器 |
| API 集成预览 | `api-preview` | 下游消费 | 优化后的提示词可直接传递给预览模块生成视频 |

### 2.2 功能详细描述

#### 2.2.1 自然语言→结构化提示词

- **描述**：用户在输入框中输入任意自然语言创意描述（中/英文均支持），系统调用 LLM（优先 GPT-4o，备选 Claude 3.5 Sonnet）将其重写为符合 Seedance 2.0 最优结构的提示词，通过 SSE 流式输出到页面
- **输入**：
  - 用户自然语言描述（字符串，1~2000字）
  - 可选：输出语言偏好（中文/英文，默认英文，因 Seedance 英文提示词效果更优）
  - 可选：视频时长目标（5s/10s，影响运动描述密度）
- **处理逻辑**：
  1. 输入有效性校验（非空、长度≤2000字）
  2. 构建 Seedance 专用 System Prompt（包含六维结构定义、Seedance 禁忌词、最佳实践案例）
  3. 调用 LLM API，流式返回结构化提示词
  4. 解析返回内容，按维度拆分并高亮展示（主体/场景/镜头/光影/运动/风格各色标签）
  5. 生成完成后自动触发质量评分（异步）
- **输出**：结构化提示词文本（英文优先，含维度标签高亮）+ 原始完整提示词文本（可一键复制）
- **异常场景**：
  - LLM API 超时（>10s）：终止流式请求，显示「生成超时，请重试」
  - LLM API 返回空内容：重试1次，仍失败则提示用户
  - 输入包含敏感词汇：前端校验拦截，提示「请修改输入内容后重试」

#### 2.2.2 多维度参数调校面板

- **描述**：优化结果展示后，用户可通过可视化参数面板对四个核心维度进行精细调整，每次调整后可重新生成或实时预览调整后的提示词文本变化
- **输入**：
  - 镜头类型选择（下拉菜单：推镜/拉镜/平移/俯拍/仰射/跟随/特写/全景 等12种）
  - 光影风格滑块（柔和自然↔戏剧高对比，7档）
  - 运动速度选择（慢动作/正常/快节奏）
  - 风格标签多选（写实/电影感/动漫/赛博朋克/复古/极简 等18种预设）
- **处理逻辑**：
  1. 参数变更时，实时更新提示词预览文本（本地字符串替换，无需重新调用 LLM）
  2. 用户点击「基于参数重新优化」时，将调整后的参数注入 System Prompt，重新调用 LLM
  3. 参数状态本地缓存（LocalStorage），刷新后保留
- **输出**：实时更新的提示词预览文本；点击「重新优化」后返回新的完整结构化提示词
- **异常场景**：
  - 参数冲突（如同时选择「慢动作」和「快节奏」）：系统自动互斥，取消前一个选择

#### 2.2.3 提示词质量评分

- **描述**：对生成的结构化提示词进行质量评估，输出维度覆盖率、语义清晰度、Seedance 兼容性三个子分，综合给出 0-100 质量分及改进建议
- **输入**：已生成的结构化提示词文本
- **处理逻辑**：
  1. 检查六维结构的覆盖率（每个维度是否有内容）
  2. 检测 Seedance 已知禁用词/低效词（如「beautiful」单独使用、过于抽象的形容词）
  3. 评估提示词总长度与 Seedance 推荐长度（75-150 tokens）的匹配度
  4. 综合计算质量分并生成 1-3 条具体改进建议
- **输出**：质量评分（0-100）+ 维度覆盖率雷达图（6维）+ 改进建议列表
- **异常场景**：评分服务超时（>5s）：静默跳过，不影响核心优化功能

#### 2.2.4 一键复制与格式导出

- **描述**：用户可将最终提示词一键复制到剪贴板 或 导出为 .txt 文件
- **输入**：用户点击「复制」或「导出 .txt」按钮
- **处理逻辑**：
  - 复制：调用 `navigator.clipboard.writeText()`，复制纯文本版本（不含 HTML 标签）
  - 导出：生成 Blob 对象，触发浏览器下载 `seedance-prompt-{时间戳}.txt`
- **输出**：剪贴板内容更新（复制成功提示）或浏览器下载文件
- **异常场景**：浏览器剪贴板权限被拒绝：显示文本选择框让用户手动复制

## 5. 交互设计与原型

### 5.1 关键交互流程

```
用户进入编辑器页面
  → 在输入区输入创意描述（带字数实时计数）
    → 点击「优化」按钮
      → 发起 SSE 请求（按钮变为「生成中...」禁用状态）
        → 流式文字逐字输出到结果区
          → 输出完成（按钮恢复）→ 异步展示质量评分
            → 用户调参（实时更新预览）
              → 一键复制 / 保存到历史 / 发起API预览
```

## 6. 依赖、风险与技术参考

### 6.1 外部依赖

| 依赖项 | 提供方 | 状态 | 影响范围 |
|--------|--------|------|----------|
| GPT-4o API | OpenAI | ✅ 已确认（商业可用） | 核心提示词优化功能 |
| Claude 3.5 Sonnet API | Anthropic | ✅ 已确认（备选） | LLM 备选方案（故障切换） |

### 6.2 风险项

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|----------|
| LLM 输出质量不稳定（Seedance 专项提示词效果差） | 中 | 高 | 建立 Seedance 专用 System Prompt 反复迭代测试；收集用户反馈数据持续调优；设置 A/B 测试框架比较不同提示词策略 |
| OpenAI API 故障导致服务中断 | 低 | 高 | 实现 Claude 备用通道自动切换；在 Redis 缓存历史优化结果 |
| LLM API 成本超预期 | 中 | 中 | 设置每用户每日调用限额（Free，10次/天）；启用结果缓存（相似输入命中缓存） |

### 6.3 技术参考

- **模块级架构文档**：[architecture-seedance-prompt-prompt-optimizer.md](architecture-seedance-prompt-prompt-optimizer.md) v1.0.0
- **核心数据对象**：`prompts`（输入文本 + 六维结构化 JSON + quality_score）、`prompt_versions`（版本迭代历史）
- **核心 API 端点**：`POST /api/v1/prompt/optimize`（SSE 流式），`POST /api/v1/prompt/refine`（参数重优化 SSE），`POST /api/v1/prompt/score`（质量评分）
- **LLM 集成模式**：Server-Sent Events（SSE）流式输出；主模型 OpenAI GPT-4o，备用 Claude 3.5 Sonnet；后端 `LLMProviderAdapter` 封装主备切换
- **前端核心组件**：`PromptInputPanel`、`PromptOutputPanel`（SSE 渲染）、`ParameterTuningPanel`、`QualityScoreCard`、`CopyExportPanel`
- **状态管理**：Zustand `promptStore`（inputText, outputTokens, isStreaming, qualityScore）+ `paramsStore`（镜头/光影/运动/风格参数）
