## 1. 模块概述

### 1.1 模块职责

Prompt 构建器是产品的**核心交互模块**，让用户通过结构化参数表单（而非直接手写文本）构建视频 Prompt。用户在表单中选择镜头类型、运镜方式、场景风格等参数，系统自动组合生成符合目标模型语法规范的完整 Prompt 文本，大幅降低 Prompt 创作的学习门槛。

### 1.2 模块范围

| 包含 | 不包含 |
|------|--------|
| 结构化参数表单（普通模式和专家模式） | 视频生成本身（仅生成 Prompt 文本）|
| Prompt 文本生成与展示 | 图片/视频上传（逆向解析列为二期）|
| 一键复制/导出到剪贴板 | Prompt 效果预览（生成真实视频） |
| Prompt 变体批量生成（P2） | 用户账号和权限管理（属于基础服务层）|

### 1.3 相关模块

| 模块 | 标识 | 关系 | 说明 |
|------|------|------|------|
| 多模型适配 | `model-adapter` | 上游依赖 | 提供各模型的参数 Schema 和格式化规则，构建器表单基于 Schema 动态渲染 |
| 模板库 | `template-library` | 上游数据来源 | 用户从模板库应用模板后，模板参数集填充到构建器表单 |
| 历史与分享 | `history-share` | 下游消费 | 构建器每次生成 Prompt 后，结果自动推送到历史记录模块保存 |

## 2. 功能需求

### 2.1 功能概览

| 功能点 | 描述 | 优先级 | R | I | C | E | RICE 分 | 状态 |
|--------|------|--------|---|---|---|---|---------|------|
| 结构化参数输入 | 场景/镜头/运镜/时长/风格等字段化输入表单 | P0 | 9 | 3 | 100% | 1.5 | **18** | 待开发 |
| Prompt 智能生成 | 根据参数自动组合生成符合模型语法的完整 Prompt | P0 | 9 | 3 | 100% | 1.0 | **27** | 待开发 |
| 一键复制/导出 | 生成结果一键复制到剪贴板，标注目标模型 | P0 | 9 | 2 | 100% | 0.2 | **90** | 待开发 |
| 专家模式 | 切换展开全部高级参数字段（默认折叠） | P1 | 4 | 2 | 80% | 0.5 | **12.8** | 待开发 |
| 批量生成 | 基于当前参数一次性生成 3-5 条 Prompt 变体 | P2 | 5 | 2 | 50% | 1.0 | **5** | 待开发 |

### 2.2 功能详细描述

#### 2.2.1 结构化参数输入

- **描述**：构建器提供结构化表单，将视频 Prompt 的关键要素拆解为独立字段。普通模式展示 6-8 个最常用字段；专家模式展示全部字段（见 2.2.4）。
- **输入**：
  - **场景描述**（必填，文本输入）：主体内容、环境背景，如"霓虹灯下的街道，雨夜"
  - **主体/主角**（选填，文本输入）：如"一名穿着风衣的女性"
  - **镜头类型**（必填，单选下拉）：特写/中景/全景/广角/俯视/仰视
  - **运镜方式**（选填，多选）：静止/推镜/拉镜/横移/环绕/手持抖动
  - **视频时长**（必填，下拉/数字输入）：4s / 5s / 8s / 10s / 自定义（受模型限制）
  - **画面风格**（选填，单选下拉）：写实/电影感/动漫/水墨/赛博朋克/自定义
  - **光影效果**（选填，单选）：自然光/黄金时刻/蓝调时刻/霓虹灯/工作室灯光
- **处理逻辑**：表单字段基于 `model-adapter` 模块提供的当前模型 Schema 动态渲染；必填字段标注红色星号；参数修改时实时更新右侧 Prompt 预览区
- **输出**：右侧预览区实时展示当前参数对应的 Prompt 文本草稿
- **异常场景**：必填字段为空时点击"生成"按钮置灰，字段悬停提示"此字段必填"

#### 2.2.2 Prompt 智能生成

- **描述**：用户点击"生成 Prompt"按钮，系统将表单参数经 `model-adapter` 格式化引擎处理，输出符合目标模型官方语法规范的完整 Prompt 文本。
- **输入**：当前表单中填写的所有参数 + 目标模型选择（来自 `model-adapter`）
- **处理逻辑**：
  1. 校验必填字段完整性（前端）
  2. 调用 `/api/prompts/generate` 接口，传入参数集和模型 ID
  3. 后端依据该模型的 Prompt Schema 将参数拼装为完整文本
  4. 可选增强：若启用 LLM 优化，对生成的 Prompt 做语义润色（非必要路径）
- **输出**：在结果区展示完整 Prompt 文本，标注字符数和目标模型名称
- **异常场景**：接口超时（>3s）展示 Toast 错误提示，参数不清空；LLM 优化失败时降级为规则拼接结果

#### 2.2.3 一键复制/导出

- **描述**：结果展示区提供"复制"按钮，一键将完整 Prompt 文本复制到剪贴板；复制成功后按钮文字临时变为"已复制 ✓"（2s 后恢复）；同时自动触发保存到历史记录。
- **输入**：用户点击"复制"按钮
- **处理逻辑**：调用 Clipboard API 写入文本；调用历史记录自动保存（见 `history-share` 模块）
- **输出**：剪贴板内容更新；历史记录新增一条；Toast 提示"已复制到剪贴板"
- **异常场景**：浏览器不支持 Clipboard API 时降级为文本框选中 + 提示"请手动复制"

#### 2.2.4 专家模式

- **描述**：构建器右上角提供"专家模式"开关；开启后展开所有高级参数字段，关闭则折叠为普通模式。用户偏好持久化（localStorage）。
- **额外字段（专家模式）**：
  - **色彩调色板**（如温暖色调/冷色调/高对比度）
  - **画面比例**（16:9 / 9:16 / 1:1）
  - **帧率**（24fps / 30fps / 60fps，受模型支持限制）
  - **负向 Prompt**（描述不希望出现的内容，部分模型支持）
  - **参考风格关键词**（如 cinematic, bokeh, shallow depth of field）
- **异常场景**：某模型不支持的参数字段展示为置灰状态 + Tooltip "当前模型不支持此参数"

#### 2.2.5 批量生成（P2）

- **描述**：在结果区提供"生成变体"按钮；点击后系统基于当前参数自动微调关键词，生成 3-5 条风格相近但表述不同的 Prompt 变体，供用户对比选择。
- **输入**：已完整填写的当前参数 + 用户点击"生成变体"
- **处理逻辑**：调用 LLM API 生成变体（本功能强依赖 LLM，无降级方案）
- **输出**：以卡片列表形式展示 3-5 条变体 Prompt，每条可独立复制

## 4. 测试要点

### 4.1 核心测试场景

| 场景 | 测试步骤 | 预期结果 | 测试类型 |
|------|----------|----------|----------|
| 普通模式完整生成流程 | 填写所有必填字段 → 点击"生成" → 复制 | 生成成功，Prompt 格式正确，复制到剪贴板 | UI + API |
| 必填字段为空时 | 不填场景描述 → 点击"生成" | 按钮禁用，字段标红 | UI |
| 切换不同模型 | 从 Kling 切换为 Sora → 查看 Prompt 格式变化 | Prompt 语法格式随模型变化（测试用例需覆盖 3 个主流模型） | Unit |
| 专家模式切换 | 开启专家模式 → 填写负向 Prompt → 生成 | 负向 Prompt 正确体现在输出中 | UI + API |
| 生成超时处理 | Mock 接口延迟 > 3s | 展示超时 Toast，参数保留 | UI |

### 4.2 边界条件

- 场景描述超过 500 字符时的截断/提示行为
- 运镜多选超过 3 个时是否有限制或警告
- 模型切换时原有参数保留规则（仅格式变，数据不清空）

### 4.3 测试类型分布

```
UI 测试：60%（表单交互、状态变化、复制行为）
API 测试：25%（生成接口正确性、响应时间）
Unit 测试：15%（Prompt 格式化函数、Schema 校验函数）
```

## 6. 依赖、风险与技术参考

### 6.1 模块间依赖

- 强依赖 `model-adapter` 的 Schema API；Schema 接口不可用时构建器无法渲染参数表单
- 软依赖 LLM API（仅 P2 批量生成功能需要）

### 6.2 风险

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 模型更新导致参数 Schema 失效 | 高 | 高 | Schema 版本化管理，独立配置可热更新 |
| LLM API 成本超预期 | 中 | 中 | P2 批量生成功能设为付费增值功能 |

### 6.3 技术参考

> 此区域由 `architect` Skill 填充正式架构方案后更新。

- 参数表单动态渲染建议基于 JSON Schema + React Hook Form
- Prompt 格式化引擎建议独立为 `prompt-engine` 服务，便于各模型 Schema 热更新
