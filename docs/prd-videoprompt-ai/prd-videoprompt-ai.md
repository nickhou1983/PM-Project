## 1. 背景与目标

### 1.1 项目背景

随着 Runway Gen-4、Kling AI、Google Veo 3 等视频大模型的快速发展，AI 视频生成已从专业领域走向大众市场。然而，不同模型对提示词（Prompt）的格式要求、参数规范和表达风格存在显著差异，用户在切换模型时面临巨大的学习成本和适配困难。

当前市场上缺乏一个统一的、跨模型的提示词管理和转换平台，用户不得不：
- 手动学习每个模型的提示词语法和限制
- 反复试错调整提示词以获得理想效果
- 无法复用已有提示词资产跨模型使用

VideoPrompt AI 旨在成为视频大模型提示词的"通用翻译器"和"智能助手"，降低 AI 视频创作的技术门槛，让更多创作者专注于创意本身。

> 立项验证详情见附录 A：需求分析报告。

### 1.2 业务目标

| 目标 | 描述 | SMART 标准 |
|------|------|-----------|
| **降低使用门槛** | 让非技术用户也能高效使用视频大模型 | 上线 3 个月内，非技术用户占比 ≥30% |
| **提升创作效率** | 将提示词编写时间缩短 50% 以上 | 用户平均提示词生成时间 ≤2 分钟 |
| **建立用户粘性** | 通过模板库和社区形成网络效应 | 上线 6 个月，7 日留存率 ≥30% |

### 1.3 成功指标

| 指标 | 目标值 | 衡量方式 |
|------|--------|----------|
| DAU（日活跃用户） | ≥500（上线 3 个月） | Google Analytics / 自建埋点 |
| 提示词转换成功率 | ≥85% | 后端日志统计（成功转换数/总转换请求数） |
| 7 日用户留存率 | ≥30% | 用户行为分析（Mixpanel/Amplitude） |
| 平均提示词生成时间 | ≤2 分钟 | 前端埋点（从开始输入到完成生成） |
| 付费转化率 | ≥3%（上线 6 个月） | 订阅漏斗分析 |
| NPS（净推荐值） | ≥40 | 定期用户调研问卷 |

## 2. 用户画像

| 角色 | 特征 | 核心需求 | 使用场景 |
|------|------|----------|----------|
| **视频创作者** | 25-40 岁，有短视频/影视/广告制作经验，熟悉至少一款视频大模型 | 快速将已有提示词适配到不同模型，提升跨平台创作效率 | 在 Runway 上优化过的提示词需要迁移到 Kling AI 使用；需要同一场景在多个模型上对比效果 |
| **非技术用户** | 20-35 岁，对 AI 视频感兴趣但缺乏提示词编写经验，可能是自媒体创作者、营销人员 | 用自然语言描述想法即可获得专业提示词，无需学习各模型语法 | 想生成一段产品宣传视频但不知道如何写提示词；看到别人的 AI 视频也想尝试 |
| **内容运营者** | 28-45 岁，负责品牌方或 MCN 的视频内容批量生产 | 批量管理和复用提示词模板，标准化内容生产流程 | 需要为客户批量生成不同风格的视频素材；管理团队的提示词资产库 |

> ⚠️ **假设性画像，建议后续验证**。以上用户画像基于需求分析和竞品调研推导，无实际用户调研数据支撑（N=0）。建议在 MVP 上线后通过用户访谈（≥5 人）和行为数据验证。

## 6. 交互设计

### 6.1 关键页面/流程

**核心流程 1 — 提示词转换**：

```
粘贴提示词 → 自动识别源模型 → 选择目标模型 → 一键转换 → 预览对比 → 复制/导出
```

**核心流程 2 — 提示词生成**：

```
输入自然语言描述 → 选择目标模型 → AI 生成提示词 → 查看多方案 → 选择/编辑 → 复制/保存
```

**核心流程 3 — 模板使用**：

```
浏览模板库 → 筛选/搜索 → 查看模板详情 → 一键使用(跳转到转换/生成) → 保存为个人模板
```

### 6.3 异常场景处理

| 异常场景 | 用户表现 | 处理方式 |
|----------|----------|----------|
| 提示词格式无法识别 | 转换按钮置灰，显示提示 | 提示"无法识别提示词格式，请检查输入或手动选择源模型" |
| LLM API 调用超时 | 加载动画超过 5s | 显示"生成时间较长，请稍候"，30s 后提供重试按钮 |
| 目标模型暂不支持 | 模型选择列表标灰 | 标注"即将支持"并提供反馈入口 |
| 网络断开 | 操作无响应 | Toast 提示"网络连接中断，请检查网络后重试" |
| 免费额度用完 | 点击转换/生成无反应 | 弹窗提示"今日免费额度已用完"，引导升级 Pro |

## 7. 技术方案概要

### 7.1 技术选型

| 层级 | 技术选型 | 说明 |
|------|----------|------|
| 前端 | React (Next.js 15) | SSR 支持 SEO，App Router 架构，TypeScript |
| UI 框架 | Tailwind CSS + shadcn/ui | 快速构建一致性 UI，组件可定制 |
| 后端 | Python (FastAPI) | 与 LLM 生态兼容性强，异步 IO 高性能 |
| LLM 集成 | LangChain / 直接 API | 提示词转换和生成的核心引擎 |
| 数据库 | PostgreSQL + Redis | 关系型数据存储 + 缓存/会话管理 |
| 对象存储 | S3 兼容存储 | 用户上传的参考图片等 |
| 部署 | Docker + 云平台（待定） | 容器化部署，支持水平扩展 |
| 监控 | Sentry + Prometheus + Grafana | 错误追踪 + 指标监控 + 可视化 |

### 7.2 系统架构概述

```
┌─────────────┐     ┌──────────────┐     ┌─────────────────┐
│  Next.js     │────▶│  FastAPI      │────▶│  LLM Services   │
│  Frontend    │     │  Backend      │     │  (GPT/Claude)   │
└─────────────┘     ├──────────────┤     └─────────────────┘
                    │  PostgreSQL   │
                    │  Redis Cache  │
                    └──────────────┘
```

核心模块：
- **Prompt Parser**：解析输入提示词，识别源模型和结构化参数
- **Prompt Transformer**：基于 LLM 进行跨模型提示词转换
- **Prompt Generator**：自然语言到结构化提示词的生成引擎
- **Model Registry**：视频大模型参数和能力的知识库

### 7.3 关键接口定义

| 接口 | 方法 | 路径 | 描述 |
|------|------|------|------|
| 提示词转换 | POST | /api/v1/prompts/convert | 将提示词从源模型转换到目标模型 |
| 提示词生成 | POST | /api/v1/prompts/generate | 基于自然语言描述生成提示词 |
