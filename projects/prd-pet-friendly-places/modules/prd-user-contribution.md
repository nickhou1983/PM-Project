## 1. 模块概述

### 1.1 模块职责

用户上报与 UGC 模块负责通过众包模式让用户贡献宠物友好场所数据，包括上报新场所、对已有场所信息纠错和补充。该模块是 App 数据冷启动和长期数据增长的核心驱动力，通过社区力量持续完善场所数据库。

### 1.2 模块范围

| 包含 | 不包含 |
| ---- | ------ |
| 上报新的宠物友好场所 | 场所搜索与地图展示（属于 place-discovery 模块） |
| 对已有场所信息纠错/补充 | 场所评价发表（属于 place-detail 模块） |
| 上报/纠错内容的后台审核 | 商家自主入驻和管理 |
| 上报贡献激励（积分/徽章） | 用户登录和账户管理（属于 user-center 模块） |

### 1.3 相关模块

| 模块 | 标识 | 关系 | 说明 |
| ---- | ---- | ---- | ---- |
| 场所详情与评价 | `place-detail` | 双向协作 | 详情页提供"纠错"入口；审核通过后更新详情 |
| 用户中心 | `user-center` | 上游依赖 | 上报/纠错需登录；贡献记录展示在个人中心 |
| 场所发现与搜索 | `place-discovery` | 下游消费 | 审核通过的场所出现在搜索和地图中 |

## 2. 功能需求

### 2.1 功能概览

| 功能点 | 描述 | 优先级 | R | I | C | E | RICE 分 | 状态 |
| ------ | ---- | ------ | - | - | - | - | ------- | ---- |
| 上报新场所 | 用户提交新的宠物友好场所信息 | P1 | 7 | 2 | 60% | 1.5 | 5.6 | 待开发 |
| 场所纠错 | 对已有场所信息提交修改建议 | P1 | 6 | 1 | 60% | 0.5 | 7.2 | 待开发 |
| 内容审核 | 对上报/纠错内容进行审核处理 | P1 | 5 | 3 | 100% | 2.0 | 7.5 | 待开发 |

### 2.2 功能详细描述

#### 2.2.1 上报新场所

- **描述**：登录用户通过表单提交新发现的宠物友好场所信息
- **输入**：场所名称、地址（支持地图选点）、场所类型、宠物政策、照片、补充说明
- **处理逻辑**：
  1. 检查用户登录状态
  2. 填写场所基本信息：
     - 必填：场所名称、地址（支持地图选点和文字输入）、场所类型（餐厅/咖啡馆/公园/商场/酒店/宠物店/其他）
     - 选填：营业时间、联系电话
  3. 填写宠物政策：
     - 允许的宠物类型（多选）
     - 犬种/体重限制
     - 清洁费/押金
     - 宠物设施（多选）
     - 特殊规定（文字输入）
  4. 上传照片（1-9 张）
  5. 补充说明（文本框，限 200 字）
  6. 提交后进入审核队列
  7. 审核通过后场所上线，通知上报者
- **输出**：提交成功页面，显示"感谢您的贡献！我们将在 24 小时内审核"
- **异常场景**：
  - 重复上报：基于名称+地址去重，提示"该场所已收录，可查看或纠错"
  - 地址无法定位：允许在地图上手动标记位置

#### 2.2.2 场所纠错

- **描述**：用户对已有场所的信息提交修改建议
- **输入**：场所 ID、纠错字段、修改建议
- **处理逻辑**：
  1. 从场所详情页点击"信息纠错"按钮
  2. 展示当前场所信息（只读），用户选择需要纠错的字段
  3. 纠错类型：
     - 信息有误（名称/地址/电话/营业时间）
     - 宠物政策变更（政策调整/取消宠物友好）
     - 场所已关闭
     - 新增信息补充
  4. 用户填写修改建议和补充说明
  5. 可选：上传佐证照片
  6. 提交后进入审核队列
- **输出**：纠错提交成功提示
- **异常场景**：
  - 相同字段重复纠错（待审核中）：提示"该字段已有待审核的纠错，请等待处理"

#### 2.2.3 内容审核

- **描述**：后台对用户提交的上报和纠错内容进行审核，确保数据准确性
- **输入**：待审核的上报/纠错提交
- **处理逻辑**：
  1. 自动审核（一期简化）：
     - 文字内容敏感词过滤
     - 照片 NSFW 检测
     - 地址有效性校验（调用地图 API 反查）
  2. 人工审核（队列处理）：
     - 审核场所信息是否真实
     - 审核宠物政策是否合理
     - 审核照片是否与场所相关
  3. 审核结果：通过/拒绝/需补充信息
  4. 通过后自动更新场所数据库
  5. 推送审核结果通知给提交者
- **输出**：审核通过：场所上线/信息更新；审核拒绝：通知用户原因
- **异常场景**：
  - 审核超时（>48h 未处理）：自动升级到管理员

## 5. 交互设计与原型

### 5.1 关键交互流程

```text
点击"上报场所" → 填写基本信息 → 地图选点 → 填写宠物政策 → 上传照片 → 提交 → 等待审核 → 收到通知
```

```text
场所详情页 → 点击"纠错" → 选择纠错字段 → 填写修改建议 → 提交 → 等待审核 → 收到通知
```

### 6.2 风险项

| 风险 | 概率 | 影响 | 应对措施 |
| ---- | ---- | ---- | -------- |
| 上报数据质量低 | 高 | 高 | 必填字段约束 + 审核机制 + 贡献者信用体系 |
| 审核人力不足 | 中 | 中 | 一期先自动审核为主，人工审核为辅 |
| 恶意灌水上报 | 低 | 中 | 同一用户每日上报上限（5 条），异常行为检测 |
