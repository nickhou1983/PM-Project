## 1. 背景与目标

### 1.1 项目背景

中国宠物市场规模已突破 3000 亿元，宠物犬猫数量达 1.87 亿只。随着"萌宠经济"蓬勃发展，越来越多的宠主选择带毛孩子出行。然而，**38% 的宠主认为携宠出行困难是养宠主要痛点**，**80% 的携宠用户在出行时会主动搜索宠物友好地点**。

当前宠物友好信息分散在大众点评、小红书、滴滴等多个综合平台的子功能中，中国大陆市场上**没有一款像 BringFido/DogPack 一样的独立垂直宠物友好场所 App**。信息碎片化、标准不统一、到店后"名不副实"是宠主们面临的核心痛点。

立项验证详情见附录 A。

### 1.2 业务目标

1. 打造中国首个垂直的宠物友好场所发现与导航平台
2. MVP 阶段聚焦 1-2 个城市（上海/成都），收录 ≥2000 个宠物友好 POI
3. 上线 3 个月内获取 ≥10,000 注册用户，MAU ≥3,000
4. 建立 UGC 内容生态，用户上报场所占总 POI 的 ≥20%

### 1.3 成功指标

| 指标 | 目标值 | 衡量方式 |
| ---- | ------ | -------- |
| MAU（月活跃用户） | ≥3,000（3 个月内） | 埋点统计 |
| POI 收录数 | ≥2,000（上线时） | 后台数据统计 |
| 用户上报场所数 | 占总 POI ≥20% | 后台 UGC 统计 |
| 7 日留存率 | ≥25% | 埋点统计 |
| 30 日留存率 | ≥10% | 埋点统计 |
| App Store 评分 | ≥4.0 | 应用商店 |

## 6. 交互设计

### 6.1 关键页面/流程

**核心流程 1：场所发现与导航**

```
打开 App → 自动定位 → 地图展示附近 POI → 点击标记 → 查看场所详情 → 一键导航
```

**核心流程 2：搜索与筛选**

```
搜索栏输入关键词 → 选择筛选条件（类型/距离/宠物大小） → 查看搜索结果列表 → 点击场所 → 查看详情
```

**核心流程 3：用户上报**

```
点击"上报场所" → 填写场所信息表单 → 上传照片 → 提交 → 进入审核 → 审核通过后展示
```

### 6.3 异常场景处理

| 异常场景 | 用户表现 | 处理方式 |
| -------- | -------- | -------- |
| 定位权限未授予 | 地图无法定位当前位置 | 弹窗引导用户开启定位权限，提供手动选择城市的降级方案 |
| 网络异常 | 地图/列表加载失败 | 展示缓存数据（如有），显示"网络异常，请重试"提示 |
| 搜索无结果 | 列表为空 | 展示空状态插图，引导用户扩大搜索范围或上报场所 |
| 上报内容违规 | 提交被拒绝 | 展示具体违规原因，引导修改后重新提交 |

## 7. 技术方案概要

### 7.1 技术选型

| 层级 | 技术选型 | 说明 |
| ---- | -------- | ---- |
| 前端 | React Native / Flutter | 跨平台移动 App，同时覆盖 iOS 和 Android |
| 后端 | Node.js + Express / NestJS | 轻量级 REST API，快速迭代 |
| 数据库 | PostgreSQL + PostGIS | 关系型数据库 + 地理空间查询扩展 |
| 地图 SDK | 高德地图 SDK | 国内主流地图服务，LBS + 导航 |
| 对象存储 | 阿里云 OSS | 图片存储 |
| 部署 | 阿里云 ECS / Serverless | MVP 阶段轻量部署 |

### 7.2 系统架构概述

系统采用前后端分离架构，移动端 App 通过 REST API 与后端通信。核心模块包括：

- **POI 服务**：管理宠物友好场所的 CRUD 和地理空间查询
- **用户服务**：注册登录、宠物档案、收藏管理
- **UGC 服务**：场所上报、评价发表、内容审核
- **地图服务**：封装高德地图 SDK 的定位、搜索、导航能力

### 7.3 关键接口定义

| 接口 | 方法 | 路径 | 描述 |
| ---- | ---- | ---- | ---- |
| 获取附近场所 | GET | /api/places/nearby | 基于经纬度和半径查询附近 POI |
| 搜索场所 | GET | /api/places/search | 关键词+筛选条件搜索 |
| 获取场所详情 | GET | /api/places/:id | 获取单个场所完整信息 |
| 获取场所评价 | GET | /api/places/:id/reviews | 分页获取场所评价列表 |
| 发表评价 | POST | /api/places/:id/reviews | 提交评价（需登录） |
| 上报新场所 | POST | /api/places/report | 用户上报新场所（需登录） |
| 收藏/取消收藏 | POST | /api/favorites/toggle | 收藏或取消收藏场所 |
| 获取收藏列表 | GET | /api/favorites | 获取用户收藏的场所列表 |

## 10. 术语表

| 术语 | 定义 |
| ---- | ---- |
| POI | Point of Interest，兴趣点，指地图上的一个具体场所位置 |
| 宠物友好场所 | 允许或欢迎顾客携带宠物进入的商业/公共场所 |
| UGC | User Generated Content，用户生成内容，包括评价、照片、场所上报 |
| LBS | Location Based Service，基于位置的服务 |
| 宠物政策 | 场所对携宠入内的具体规定（限制犬种/体重、清洁费、宠物专区等） |
| RICE 评分 | 功能优先级排序框架（Reach × Impact × Confidence / Effort） |
| MVP | Minimum Viable Product，最小可行产品 |

## 附录 A：需求分析报告

> 以下为立项前的需求分析与验证报告（由 `pm_assistant` Agent 输出），完整报告见 [analysis-report-pet-friendly-places.md](analysis-report-pet-friendly-places.md)。

### A.1 需求概述

- **核心功能点**：场所搜索与筛选、地图定位与导航、场所详情与评价、用户上报（UGC）、收藏与分享
- **目标用户**：25-40 岁一二线城市养宠人群
- **痛点**：宠物友好信息分散、标准不统一、到店后名不副实

### A.2 内部查重结果

飞书知识库查重结果：搜索「宠物友好」「携宠出行」「宠物地图」三个关键词，均无匹配文档。判定为 🆕 全新需求。

### A.3 竞品分析

海外：BringFido（老牌领头）、DogPack（社区驱动，100 万+下载）、DogMap（非营利，75 万+标注点）
国内：大众点评宠物友好地图（6 城 865+ 场所，仅为子功能）、滴滴宠物出行（北京/上海/成都，3000+ 门店）
**市场空白**：中国大陆无独立垂直的宠物友好场所 App。

### A.4 价值评估

| 维度 | 评分 |
| ---- | ---- |
| 创新度 | 3/5 |
| 市场需求度 | 5/5 |
| 实现难度 | 3/5 |
| 竞争优势 | 3/5 |
| 商业可行性 | 4/5 |
| **综合评分** | **3.6/5** |

### A.5 结论与建议

**结论**：✅ 建议推进。市场需求强烈（320 亿+宠物出行市场），技术实现无阻塞，核心挑战在 POI 数据冷启动。
